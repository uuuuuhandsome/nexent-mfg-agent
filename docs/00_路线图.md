# 项目路线图

> 最后更新：2026-10-25

## 一句话目标

做一个能读懂数控机床的**日志、维修手册、安全标准**，并且每条结论都能指回原文的智能体，跑在 Nexent 上，代码开源。

---

## 比赛到底要什么（翻译成人话）

| 赛题要求 | 人话 | 我们的对应 |
|---|---|---|
| 多模态异构数据统一识别 | 什么格式的文件都要能读 | 知识库分 4 类：手册 / 标准 / 数据 / 经验 |
| 低资源本体半自动构建 | 让它自己整理术语表，边干边学 | 6 类实体 + 5 类关系的轻量图谱 |
| 深度集成 MCP 与 Skills | 该用工具时用工具 | 自研 3 个 MCP Server |
| 跨文档多跳 + 可溯源 | 答案藏在几个文件里，还要能指页码 | 四跳链路 + [文档|页码|条款] 标签 |
| 基于 Nexent 可运行 | 必须用这个平台 | ✅ 已完成 |

## 三条纪律

1. **每天至少一次提交**，哪怕只改一行。提交历史是评委判断“真在做还是在赶工”的依据。
2. **不提交密钥**。API Key 只放本地 `.env`，`.gitignore` 已经排除。
3. **不提交大文件**。单文件上限 100MB，原始手册和标准全文放外部链接，仓库里只放片段。

---

## 技术选型备注

- **图谱**先用 JSON / NetworkX，不上 Neo4j（两周时间不够）
- **结构化数据**（CSV）走 MCP 工具直读，不进知识库（保住行号溯源）
- **非结构化数据**（PDF/手册/标准）走知识库检索
- 这个拆分本身就是赛题「检索-推理双驱动」的体现，答辩时要讲清楚
