# 运维排错手册

> 记录本项目部署 Nexent 过程中实际踩过的坑。每条都按「现象 → 原因 → 解决」写。
> 新同学入职先读这个，能省掉一天。

---

## 快速判断

```bash
docker ps -a --format '{{.Names}}  {{.Status}}'
```

| 现象 | 大概率原因 | 跳到 |
|---|---|---|
| 登录不上 / 一直转圈 | `supabase-auth-mini` 掉了 | [问题 1](#问题-1登录不上) |
| 页面能开但功能全挂 | `nexent-config` 掉了 | [问题 1](#问题-1登录不上) |
| 知识库上传后「解析失败」 | `nexent-data-process` 没起来 | [问题 2](#问题-2入库服务不可用) |
| 上传成功但「入库失败」 | 容器访问不了外网（embedding 调不通） | [问题 3](#问题-3容器没有外网) |
| `docker pull` 卡住 / 超时 | Docker 代理指向了已关闭的梯子 | [问题 4](#问题-4拉镜像超时) |

**80% 的情况跑一次 `scripts/restart-nexent.sh` 就能解决。**

## 问题 1：登录不上

### 现象

- 输入账号密码后一直转圈，或提示登录失败
- `docker ps -a` 里看到：

```
nexent-config        Exited (127)
supabase-db-mini     Exited (127)
supabase-auth-mini   Restarting
```

### 原因

`Exited (127)` **不是「命令找不到」**，而是挂载失败：

```
error mounting ".../docker-desktop-bind-mounts/Ubuntu/docker.sock"
not a directory: Are you trying to mount a directory onto a file?
```

这些容器启动时要挂载几个宿主机文件（`docker.sock`、`init.sql`、`kong.yml`、`temp.yml`）。
**WSL 或 Docker Desktop 重启后，旧容器的挂载记录失效**，路径对不上，容器直接起不来。

断链过程：

```
supabase-db 起不来 → auth 连不上数据库，每 10 秒崩一次
                  → 登录接口拿不到 token
                  → 页面显示登录失败
```

### 解决

跑修复脚本：

```bash
bash scripts/restart-nexent.sh
```

Windows 下也可以直接双击 `scripts/restart-nexent.bat`。

**关键点**：必须 `--force-recreate`（删掉重建），`docker restart` 没用，因为挂载配置还是旧的。

### 什么时候会复发

只要 **WSL 或 Docker Desktop 重启过**：合盖睡久了、手动退出 Docker、Windows 更新、`wsl --shutdown`。

所以这不是「修一次就永久好」，而是**知道怎么快速修**。

## 问题 2：入库服务不可用

### 现象

- 知识库上传文档，状态直接变成「解析失败」
- 鼠标悬停提示：`知识库入库服务暂时不可用`
- 后端日志：`Failed to connect to data process service: Name or service not known`

### 原因

`nexent-data-process` **这个容器从来没被创建过**（不是崩了，是压根没起来）。

两个原因叠加：

1. `env/.env` 里没有 `NEXENT_DATA_PROCESS_IMAGE`（发布方漏配）
2. `docker/.env.generated` 里给的是 Docker Hub 地址，**但 Docker Hub 上没有这个镜像**，只有腾讯云仓库有

变量为空 / 镜像不存在 → 容器创建失败 → 被静默跳过。

### 解决

**① 确认镜像存在**

```bash
docker images | grep data-process
```

**② 如果镜像不存在，从腾讯云拉**

Docker Hub 上没有，只有腾讯云有：

```bash
docker pull ccr.ccs.tencentyun.com/nexent-hub/nexent-data-process:v2.7.0
```

> 如果这一步超时，见[问题 4](#问题-4拉镜像超时)。

**③ 补环境变量**

在 `deploy/env/.env` 里加一行：

```
NEXENT_DATA_PROCESS_IMAGE="ccr.ccs.tencentyun.com/nexent-hub/nexent-data-process:v2.7.0"
```

同时把 `deploy/docker/.env.generated` 里同名变量也改成这个腾讯云地址。

**④ 启动**

```bash
cd /home/fate/nexent/deploy
docker compose --env-file docker/.env.generated --env-file env/.env \
  -p nexent -f docker/compose/docker-compose.prod.yml up -d nexent-data-process
```

**⑤ 验证**

```bash
docker logs --tail 20 nexent-data-process
# 应该看到：✅ Started 3/3 services successfully
#           🌐 Starting API server on 0.0.0.0:5012
```

### 注意

**重跑 `deploy.sh` 会重新生成 `.env.generated`**，可能把这个修复覆盖掉。重跑之后要再检查一遍。

## 问题 3：容器没有外网

### 现象

- 文档「解析成功」但「入库失败」
- 悬停提示：`Elasticsearch service returned HTTP 500`
- 但 Elasticsearch 本身是健康的（`_cluster/health` 是 green）
- 后端日志真正的错误是：

```
Embedding API error after 3 attempts:
HTTPSConnectionPool(host='api.siliconflow.cn', port=443):
SSLError(SSLEOFError(8, '[SSL: UNEXPECTED_EOF_WHILE_READING]'))
```

### 原因

**容器访问不了外网**，embedding 调用打不通。

注意「E500 说 Elasticsearch」是误导——真正的错误是 embeddings 接口连不上，
知识库服务只是把异常包装成了 ES 错误。

诊断方法，从容器里测：

```bash
docker exec nexent-config curl -s -o /dev/null -m 10 -w "%{http_code}\n" https://www.baidu.com/
```

- 返回 `200` → 网络正常
- 返回 `000` / `500` → 容器没外网

常见根因：**Docker Desktop 的代理指向了一个已经关闭的梯子**（`127.0.0.1:7890`）。
梯子一关，端口没人监听，容器所有请求都打进死端口。

### 解决

Docker Desktop → **Settings → Resources → Proxies**：

| 区域 | 应该选 |
|---|---|
| Docker Desktop proxy | No proxy |
| Containers proxy | **No proxy** ← 关键，管的是容器内部程序 |

点 **Apply & restart**。

然后验证：

```bash
docker exec nexent-config curl -s -o /dev/null -m 10 -w "%{http_code}\n" https://api.siliconflow.cn/v1/models
# 期望 401（没带 key 的正常响应），说明 TLS 通了
```

> 硅基流动、DeepSeek 都是国内服务，**不需要梯子**。梯子只该影响浏览器，不该影响 Docker。

## 问题 4：拉镜像超时

### 现象

```
failed to copy: httpReadSeeker: failed open:
... net/http: timeout awaiting response headers
```

拉了几次都卡在同样的一两个 layer 上。

### 原因

Docker 守护进程走系统代理，把国内 CDN 的大文件传输拖死了。
典型症状：小镜像能拉，超过几百 MB 的必挂。

### 解决

**方案 A（推荐）：先把 Docker 代理关掉**，见[问题 3](#问题-3容器没有外网)。

**方案 B：绕过 Docker 代理，用 crane 直连**

```bash
# 装 crane（一个镜像搬运工具）
curl -sSL -o /tmp/crane.tar.gz \
  https://github.com/google/go-containerregistry/releases/latest/download/go-containerregistry_Linux_x86_64.tar.gz
tar xzf /tmp/crane.tar.gz -C /tmp crane

# 直连拉成 tar 包
/tmp/crane pull --format=tarball \
  ccr.ccs.tencentyun.com/nexent-hub/nexent-data-process:v2.7.0 \
  /tmp/dp.tar

# 导入 Docker
docker load -i /tmp/dp.tar
```

crane 走的是 WSL 自己的网络（不受 Docker 代理影响），1.9 GB 大约几分钟。

## 其他已知问题

### otel-collector 报错

```
Failed to export metrics batch due to timeout
NameResolutionError('otel-collector')
```

**可以忽略。** 监控组件没部署，不影响业务。

### raw.githubusercontent.com 下载失败

```
Failed to download stopwords from raw.githubusercontent.com
```

**可以忽略。** 停用词下载失败会用内置默认值，不影响分词和检索。

### 改了向量模型之后要重建知识库

embedding 模型一旦换掉（维度不同），**已灌的文档全部作废**，必须重建知识库重新入库。
选模型之前想清楚，别中途改。

## 检查清单（每次重启电脑后）

```
□ docker ps -a 里没有 Exited / Restarting
□ http://localhost:3000 能打开
□ 能登录
□ 知识库里随便问一个已知答案的问题，能答对
```

四条都过，就可以干活了。
